## 2026-03-07 - Path Traversal & Command Injection in Crucible Utility
**Vulnerability:** The CLI tool `src/bin/crucible.rs` accepted unvalidated string input from `std::env::args()` for the `tokens` argument. This string was directly interpolated into a log file path (`logs/crucible_{tokens}t.txt`) and passed as a command-line argument to a spawned process (`--tokens {tokens}`), exposing the application to path traversal (e.g. `../../etc/passwd`) and potential argument injection.
**Learning:** Developers often assume that CLI arguments intended to be numeric will only receive numbers, overlooking the fact that inputs are just raw strings. String interpolation and shell argument passing with unvalidated inputs are common attack vectors.
**Prevention:** Always validate and sanitize CLI inputs before using them in file paths or shell commands. For numeric values passed as strings, use `.chars().all(|c| c.is_ascii_digit())` and ensure the string is not empty (`!tokens.is_empty()`) to strictly enforce expected numeric formatting.
