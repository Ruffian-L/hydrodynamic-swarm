## 2024-05-24 - Path Traversal Vulnerability in Logs Generation
**Vulnerability:** A path traversal vulnerability existed in `src/bin/crucible.rs` where an unvalidated CLI argument (`tokens`) was directly injected into a file path `format!("logs/crucible_{}t.txt", tokens)`. This allowed an attacker to input a malicious payload like `../` to create or overwrite files outside the intended `logs/` directory.
**Learning:** Even internal developer tools and utilities must validate their inputs. Unvalidated input used in file operations is a classic entry point for path traversal attacks, allowing arbitrary file writes. The `.chars().all(|c| c.is_ascii_digit())` validation is effective, but it returns true for empty strings, which could inadvertently bypass validation if `!tokens.is_empty()` is not explicitly checked alongside it.
**Prevention:** Always validate and sanitize user input before using it in file paths. In rust, when validating numeric arguments used in file paths, enforce strict type sanitization using `.chars().all(|c| c.is_ascii_digit())` alongside an explicit `!tokens.is_empty()` check.
