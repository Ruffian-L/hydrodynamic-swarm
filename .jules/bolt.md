## 2024-05-24 - Redundant Serialization and Cloning during Cache Promotion
**Learning:** In Rust's caching implementations (e.g., TTL cache to LRU cache promotion), deserializing a value to verify it, only to immediately re-serialize the same value for storage in the new cache layer, leads to a significant and unnecessary performance hit due to redundant heap allocations and serialization overhead. Furthermore, when `cache_key` or `entry.value` variables are no longer used by the caller function, explicitly moving them (rather than calling `.clone()`) saves further unnecessary heap allocations.
**Action:** When promoting cached items across different layers (like from TTL to LRU), reuse the already serialized `entry.value` directly if the underlying byte representation hasn't changed. Always check variable scopes and use move semantics rather than `.clone()` when the source variable is no longer needed in the caller logic.
