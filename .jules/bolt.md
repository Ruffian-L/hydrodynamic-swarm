## 2024-05-24 - Eliminate redundant allocations and serialization in cache promotion
**Learning:** `LruCache::get` returns an owned `Option<CacheEntry>`, meaning we can directly use `entry.value` instead of cloning it. Furthermore, when promoting an entry from `TtlCache` to `LruCache` in `get_embedding`, we deserialize the value to return it, but then reserialize it to put it in the `LruCache`. Since `TtlCache` already stores the serialized bytes in `entry.value`, we can skip the serialization step entirely and just clone the bytes, avoiding the heap allocation and CPU cost of `bincode::serialize`.
**Action:** When a cache lookup returns an owned value, avoid cloning if the value can be moved. When promoting between caches that store identical serialized formats, reuse the existing serialized bytes rather than running the serialization routine again. Move variables into function calls (like `cache_key`) if they are no longer needed, saving a clone.
